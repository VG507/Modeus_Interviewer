# MVP: короткий технический план

Реализуем по [основному плану](Modeus_Interview_MVP_Plan.md) и [техническому контракту](Modeus_MVP_Technical_Contract.md).

| Шаг | Что сделать | Результат |
|---|---|---|
| 1 | Проверить проект про компетенции, выбрать основу, запустить вход и БД, выполнить живой запрос к LLM | Локальная основа проверена. Для закрытия шага нужен успешный `check-llm`. [Проверки](README.md#проверки) |
| 2 | Подготовить SQL-тему, анкету, источники и шесть сценариев. Зафиксировать схемы запросов, ответов и миграции для первого цикла | Общие JSON-примеры и миграции |
| 3 | Собрать сохранение ответа → экстрактор → состояние → планировщик → вопрос. Подключить синтез | Один диалог и приватная карточка |
| 4 | Прогнать сценарии и интервью со специалистом. Исправить ошибки и проверить результат | Два замечания пилота закрыты повторным разбором. Девять сценариев прошли. [Разбор пилота](docs/Step_4_Pilot.md) |
| 5 | Подключить открытое web-интервью с анкетой, распознаванием темы, проверкой ответа и контекстом текущего случая. Добавить возврат, повтор, пропуск и ручное завершение | Реализовано. Основной путь пройден в браузере. Обновлённая логика проверена через API и локальную модель |
| 6 | Добавить правку карточки, согласие, решение редактора и публичный каталог | Реализовано. В браузере проверены правка, возврат, повторная отправка, публикация и снятие. [Сценарий проверки](README.md#публикация-карточки) |
| Параллельно с 6 | Адаптировать импорт HH по четырём IT-профилям. Добавить страницу «Вакансии», ручной и еженедельный сбор, фильтры по профессии, опыту и уровню. Подключить карточки вакансий и вручную проверенные источники к уточнениям | Редактор видит карточки и основания. Интервью получает подходящую подборку заранее сохранённых материалов. Формат пригоден для будущей карты обучения |
| До проверки MVP | Добавить необязательный профиль из 1–3 проектов, применимость совета по версии и среде, еженедельную очередь материалов и датированные наблюдения из документации, DEV, daily.dev и HH | У совета видны основания и период применения. Источники проходят пересмотр через 3 года и получают явные границы применимости при возрасте свыше 5 лет |
| 7 | Проверить права, повторы, сбои, версии, качество ответов и длинные диалоги. Сравнить живость и конкретность уточнений с источниками и без них минимум для двух профилей. Довести число пилотов примерно до трёх и подготовить показ | Готовый MVP |
| После MVP | Добавить извлечение профиля из резюме с подтверждением эксперта. На накопленной истории проверить прогнозы спроса и использовать результаты при проектировании курсов | Гипотезы сравниваются с фактической долей вакансий и прогнозом «без изменений». Темы для наблюдения, практики и основной программы имеют проверяемые основания |

Во всех шагах: серверные права, постоянные ID, сохранение до LLM, защита от повторов и устаревших результатов. Один backend и одна реляционная БД; web использует общие API. Telegram/STT и расширения Dataflow — после MVP.

Нумерация здесь отличается от основного плана. Шаг 5 «Текстовое web-интервью» соответствует этапу 3 основного плана. Следующий шаг 6 «Публикация» соответствует этапу 4. Этап 5 основного плана — итоговая проверка и подготовка показа.

Работа — отдельными ветками и короткими PR. Коммиты и push агента — после разрешения владельца.
