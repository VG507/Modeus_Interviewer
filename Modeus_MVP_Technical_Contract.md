# Modeus MVP. Технический контракт

Состояние реализации на 22 ноября 2026 года. Документ описывает текущую рабочую копию. Полный список параметров и моделей ответов задаётся схемой FastAPI. Порядок запуска приведён в [README](README.md), пользовательский сценарий — в [Dataflow](Modeus_Interview_Dataflow.md).

## Компоненты и хранение

| Компонент | Реализация |
|---|---|
| Веб-интерфейс | React, TypeScript и Vite. Экраны интервью, карточек, каталога и редакторских данных. |
| API и обработка | FastAPI, SQLAlchemy и Alembic. Фоновый воркер обрабатывает этапы интервью. LLM подключается через настроенный OpenAI-совместимый API со структурированным выводом. |
| Хранилище | По умолчанию SQLite в `.work/modeus.db`. Подключение задаётся через `DATABASE_URL`. |
| Telegram | Опциональный бот с long polling для текстового интервью. Запускается при настроенном токене. Обрабатывает интервью через общий бэкенд. |

Сессии, сообщения и факты карточек хранятся в одной базе с данными сборщиков, в отдельных таблицах. В сессии сохраняются анкета, состояние кейса и текущее задание. У ответа есть ссылка на вопрос. У вопроса могут быть сохранены выдержки, предложенные модели, и отметка об использованной выдержке. У факта карточки есть ссылки на подтверждающие ответы. Для отредактированного факта отдельно сохраняется связь с исходной формулировкой. История правок и редакторских решений хранится в событиях карточки.

## Интервью и обработка

Первый вопрос выбирается из настроек темы или шаблона. Эксперт может вести открытое интервью или выбрать тему. Веб-клиент сохраняет ответ как черновик, затем отдельно отправляет его на обработку.

Воркер сохраняет ход обработки в БД. Основные стадии — начальный вопрос, извлечение, следующий вопрос и синтез. Статус сессии (`active`, `completing`, `completed`) отделён от статуса обработки (`idle`, `queued`, `running`, `failed`). Версия сессии защищает от конфликтующих изменений. Команды с `Idempotency-Key` можно безопасно повторить с теми же параметрами. Завершение создаёт одну карточку на сессию.

Извлечение опирается на текст ответа. Планировщик выбирает, что уточнить. При смене кейса история нового случая ведётся отдельно. Подтверждённая связь с предыдущим проектом позволяет использовать его условия в уточняющих вопросах. Кэш структурированных ответов модели включается настройкой `LLM_CACHE`.

## Внешние источники и сигналы

В редакторском интерфейсе вакансии и материалы доступны в одной панели по профессии. Сбор по профессии запускает отдельные сборщики HH, «Работы России», GitHub Issues и Trends, официальной документации, Hacker News, OpenAlex и Agent Skills. Объединённый запуск показывает результат каждого источника. Для HH и документации предусмотрены фоновые обновления. GitHub Issues проходят отдельную фоновую проверку.

Для контекста интервью бэкенд проверяет соответствие профессии, задаче и цели вопроса. Учитываются версия технологии и условия, если они заданы для выдержки. Модели передаётся до двух выдержек. Источник отмечается использованным, если модель вернула его номер. Для Agent Skills допустима цель проверки результата. Сборщик читает `SKILL.md` из выбранных публичных каталогов, фиксирует версию файла и сверяет извлечённые фрагменты с исходным текстом.

Из опубликованных карточек с актуальным согласием и одобрением могут подбираться обезличенные темы для уточнения при совпадении профессии, задачи и навыка. Если статус карточки или допустимость выбранного Agent Skill изменились во время генерации, бэкенд сохраняет нейтральный вопрос без этой подсказки.

## Доступ и публикация

Веб-авторизация использует серверную сессию и cookie. Интервью доступно владельцу. Редакторский интерфейс требует роль редактора. Публикация карточки доступна после согласия автора и решения редактора для текущей версии содержания.

Закрытый маршрут доказательств связывает факт с цитатой из ответа, вопросом и использованным источником. Он доступен владельцу, а редактору — для текущих фактов карточки на проверке или в публикации при отдельном согласии автора. Снятие публикации отзывает это согласие. Публичный каталог отдаёт согласованную версию содержания, исключая идентификаторы сообщений, стенограмму и историю изменений.

## Основные маршруты API

Все пути в таблице имеют префикс `/api/v1`. Параметры и точные схемы можно проверить в локальном OpenAPI (`/docs` при запуске с локальной конфигурацией).

| Область | Маршруты |
|---|---|
| Состояние и вход | `GET /health`, `POST /auth/login`, `GET /me`, `POST /auth/logout` |
| Темы и сессии | `GET /topics`, `GET/POST /interviews`, `GET /interviews/{interview_id}` |
| Ответы | `POST /interviews/{interview_id}/answers`, `PATCH /interviews/{interview_id}/answers/{answer_id}`, `POST /interviews/{interview_id}/answers/{answer_id}/submit` |
| Управление интервью | `POST /interviews/{interview_id}/skip`, `/finish`, `/retry` |
| Карточки | `GET /cards`, `GET/PATCH /cards/{card_id}`, `GET /cards/{card_id}/facts/{fact_id}/evidence` |
| Публикация | `POST /cards/{card_id}/submit-review`, `/review`, `/unpublish` |
| Каталог | `GET /catalog`, `GET /catalog/topics`, `GET /catalog/{card_id}` |
| Вакансии | `GET /vacancies`, `/vacancies/overview`, `/vacancies/candidates`. Создание и настройка профилей через `/vacancies/profiles`. Запуск сбора через `POST /vacancies/{profession_id}/collect`. |
| Источники | `GET /discovery`, `/discovery/items/{item_id}`, `/discovery/profiles`. Сбор по профессии через `GET/POST /discovery/collection/{profession_id}`. Настройки и проверка документации через `/discovery/documentation`. |

Для команд изменения интервью и карточек клиент передаёт ожидаемую версию и ключ идемпотентности. Длительные операции интервью возвращают `202`. Клиент получает текущее состояние повторным чтением сессии.
