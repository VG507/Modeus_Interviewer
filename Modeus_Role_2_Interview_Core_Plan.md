# Роль 2. Ядро интервью

Обновлено: 17 ноября 2026 года. Рабочие задачи для MVP, не отчёт о реализации.

Источник требований: [основной MVP-план](Modeus_Interview_MVP_Plan.md), разделы 4, 5, 7 и 8. Dataflow применяется после готового MVP; Telegram и STT — следующий этап. Принятый цикл: LLM-экстрактор → состояние → алгоритм-планировщик → LLM-интервьюер. Синтез реализует роль 4.

## Порядок выполнения

1. **Этап 0 — запустить основу.** Проверить инструкции, лицензию и нужные компоненты `https://github.com/kr1p043k/compare_competencies`; ориентир снимка — `9990d8b2e188722e89ef700889a14b89e25d8955`. Проверить LLM-клиент реальным запросом, БД и ошибки; с ролью 3 — вход и оболочку, с ролью 4 — хранение. Записать «берём / адаптируем / заменяем / откладываем». Ориентир аудита — до половины дня команды; блокер оценить отдельно. Секреты и чужие данные не переносить. Импорт и ML не блокируют интервью.
2. **Этап 1 — зафиксировать контракты в коде.** С ролью 4 определить схемы случая и извлечения: задача, условия, действия, решения и основания, проверка, ограничения, неизвестное; у утверждений — ссылки на сообщения. С ролью 3 зафиксировать операции создания, чтения, ответа, повтора, пропуска и завершения сессии. Запросы содержат ID, ожидаемую версию и ключ повтора; ответы — сохранённый вопрос, статус и ошибку. Точные маршруты и миграции закрепить после аудита фактического стека.
3. **Этап 1 — собрать один ход без полного web.** Проверить владельца → сохранить ответ → вызвать экстрактор → проверить схему и ссылки → применить к ожидаемой версии → выбрать цель правилом → сформулировать и сохранить один вопрос. Использовать одну настраиваемую текстовую модель с отдельными инструкциями; обычно два последовательных вызова на ответ. При завершении передать роли 4 транскрипт, структуру случая и происхождение, новый вопрос не генерировать.
4. **Этапы 1–2 — проверить содержание.** Пройти шесть сценариев роли 1 и ранний пилот. Исправить повторы, неверное извлечение и неуместные вопросы до расширения интерфейса. При большой задержке измерить этапы и сократить контекст.
5. **Этап 3 — подключить устойчивый web.** Реализовать сохранение, чтение состояния, повтор обработки и серверные проверки по таблице ниже. Передать роли 3 рабочие примеры запросов, ответов и ошибок.

## Правила планировщика

Приоритет: завершить/пропустить → существенная неоднозначность → конкретный случай → основные действия → основание решения → проверка результата → полезное уточнение ошибки/ограничения → итог.

Учитывать все сведения подробного ответа. Пустое поле само по себе не требует вопроса. Отказ закрывает ветку. После двух безрезультатных уточнений предложить другой случай или завершение. Предложить итог, когда раскрыты задача, условия, действия, основание выбора и проверка; отсутствие значимого выбора фиксировать явно. По команде человека закончить с частичным результатом.

## Обязательные проверки

| Проверка | Результат |
|---|---|
| Ошибка LLM или неверная схема | Ответ сохранён, доступен повтор |
| Повтор запроса с тем же ключом | Второй ход не создаётся |
| Параллельные запросы и устаревший результат | Один активный обработчик; новая версия не перезаписывается старой |
| Перезагрузка | Возвращаются сохранённые сообщения и текущий вопрос |
| Чужая сессия или ссылка на чужое сообщение | Доступ или результат отклонён |
| Уже известная проверка, отказ, завершение | Нет повторного вопроса, продолжения закрытой ветки или вопроса после завершения |

Правка последнего ответа разрешена до начала обработки; после — новое сообщение. Логи вызовов содержат модель, версии инструкции/схемы, длительность и ошибку без лишних копий приватного текста. Правила и переходы проверить автоматически, содержание — с ролью 1.

## Основа для следующего этапа

Операции интервью работают в backend независимо от web и используют внутренний User ID. Клиент отображает сохранённый вопрос; не выбирает его и не вызывает LLM. Постоянные ID, версия состояния и ключ повтора пригодятся Telegram. Будущий подтверждённый текст STT поступит в тот же цикл ответа. Бота, STT, аудиохранилище и дополнительные сервисы сейчас не реализуем.

## Готовность

Есть инструкция запуска, схемы и примеры API; работает цикл и передача на синтез. Пройдены проверки доступа, повторов, ошибок и сценарии роли 1. Ранний пилот разобран, критические ошибки исправлены. Изменения общих контрактов согласуются с затронутыми ролями до реализации.

Коммиты и push — только после явного разрешения владельца.
