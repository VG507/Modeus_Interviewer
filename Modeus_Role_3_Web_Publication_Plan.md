# Роль 3. Web и публикация

Обновлено: 17 ноября 2026 года. Рабочие задачи для MVP, не отчёт о реализации.

Источник требований: [основной MVP-план](Modeus_Interview_MVP_Plan.md), разделы 5–8. Dataflow применяется после готового MVP; Telegram и STT — следующий этап. Сейчас реализуем текстовый web, черновик, экран редактора и публичный каталог для хакатона.

## Порядок выполнения

| Когда | Реализовать | Зависимость и результат |
|---|---|---|
| Этап 0 | Проверить frontend и вход исходной основы совместно с ролью 2. Переиспользовать пригодный вход; при его отсутствии зафиксировать минимальный вариант с ролью 2 | Один работающий способ входа; приватные данные защищает сервер |
| Этап 1 | Получить анкету и темы роли 1, закрепить формат состояния и операции с ролью 2. Подключить минимальный экран к первому реальному ходу | Контекст → тема → сохранённый вопрос → текстовый ответ |
| Этап 2 | Дать минимальный интерфейс для раннего пилота, если он нужен; передать замечания роли 1 | Пилот не ждёт полного оформления |
| Этап 3 | Довести разговор: обработка, ошибка и повтор, пропуск, завершение, возврат после перезагрузки | Пользователь проходит интервью без помощи; ответы сохраняются, лишние ходы не появляются |
| Этап 4 | Подключить просмотр и исправление черновика, согласие и отправку на проверку; экран редактора: принять, вернуть с причиной, оставить приватно, снять публикацию | Форматы и API предоставляет роль 4; права, согласие и решение сохраняет backend |
| Этап 4 | Сделать публичные список и страницу опубликованной карточки | Каталог открывается без входа, черновики и исходные ответы посетителям недоступны |
| Этап 5 | Пройти сквозной сценарий и проверки ниже, исправить блокирующие ошибки | Инструкция запуска и перечень проверенных сценариев |

## Поведение экранов

- В интервью — один текущий вопрос. При обработке виден статус, повторная отправка заблокирована; при сбое доступен повтор без нового ввода ответа.
- Действия: «Пропустить», «Завершить», вернуться к сохранённой сессии. Правка последнего ответа — только до обработки; после неё уточнение отправляется новым сообщением.
- Черновик показывает задачу, условия, действия, решения, проверку, ограничения и пробелы; пустые дополнительные секции скрыты. Итог редактируется отдельно от истории.
- Перед публикацией — явное согласие владельца; показ авторства по его выбору. Возврат редактором показывает причину и возможность доработки. Отправка на проверку сама по себе не публикует.
- Каталог показывает название, профессию/тему, краткий смысл, содержание и доступную дату проверки. Дата интервью не подменяет дату последнего применения практики. Сырые извлечения и приватные профили в каталог не входят.

## Основа для следующего этапа

Web использует общие серверные операции и внутренние ID пользователя/сессии. Логика извлечения и выбора вопроса принадлежит backend роли 2, синтез и публикационные правила — backend роли 4. Будущие Telegram и STT подключатся к тем же операциям. Сейчас не добавляем бот, микрофон, привязку каналов, мультипрофили и объединение аккаунтов.

## Готовность

- Новый пользователь проходит путь от контекста до частичного или полного итога без инструктажа.
- Перезагрузка, двойной клик и ошибка модели не теряют ответ и не создают второй ход.
- Чужой черновик закрыт и по прямой ссылке; права редактора проверяет сервер.
- Публикация требует согласия и решения редактора. Каталог возвращает только опубликованные данные, без исходной переписки.
- Пройден путь нового интервью до публичной страницы совместно с ролями 2 и 4.

Сначала подключение к настоящему backend, затем оформление. Дополнительные фильтры, рейтинги, комментарии и обязательные демо-плашки не входят в MVP; происхождение примеров объясняется в презентации.

Коммиты и push — только после явного разрешения владельца.
