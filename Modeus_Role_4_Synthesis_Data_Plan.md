# Роль 4. Синтез карточек и данные

Обновлено: 17 ноября 2026 года. Рабочие задачи для MVP, не отчёт о реализации.

Источник требований: [основной MVP-план](Modeus_Interview_MVP_Plan.md), разделы 4–8. Dataflow применяется после готового MVP; Telegram и STT — следующий этап. Экстрактор каждого хода реализует роль 2; роль 4 использует его результат для синтеза.

Технические стыки, API, статусы и владельцы общих файлов: [общий технический контракт](Modeus_MVP_Technical_Contract.md).

## Порядок выполнения

1. **Этапы 0–1 — закрепить хранение с ролью 2.** Проверить БД основы и реализовать минимальную схему/миграции: User, Topic/Source, InterviewSession, Message, KnowledgeCard. Извлечение допустимо хранить в сообщении, структуру случая — в сессии, содержимое карточки — в JSON. С ролью 2 зафиксировать формат фактов, пробелов и ссылок на сообщения.
2. **Этап 1 — сделать синтез до полного интерфейса.** Вход: сохранённый диалог, структура случая, извлечённые сведения и происхождение. Выход: структурированная карточка и читаемый текст. Запуск — при завершении случая, включая неполный. Использовать общую настраиваемую LLM с отдельной инструкцией синтеза. Первый результат передать роли 1 на разбор, роли 3 — примеры полной и частичной карточки.
3. **Этап 2 — исправить ошибки раннего пилота.** С ролью 1 сверить утверждения с ответами: сохранить отрицания и ограничения, не превращать неудачу в совет, не добавлять типовые шаги из знаний модели. Код проверяет схему и принадлежность ссылок сессии; смысл проверяется человеком.
4. **Этап 4 — реализовать правку черновика.** Сохранить исходный синтез и явные изменения владельца простым журналом или снимком. Добавленные сведения отличать от исходных сообщений; существенные новые утверждения проверять перед публикацией. Передать роли 3 операции и ошибки.
5. **Этап 4 — реализовать публикацию.** Приватный черновик → согласие владельца и проверка → решение редактора → каталог. Реализовать возврат с причиной и снятие проблемной карточки с публикации. Правка материала на проверке отменяет применимость прежнего одобрения. Публичный API выдаёт только опубликованное представление.
6. **Этап 5 — проверить сквозной путь с ролями 1 и 3.** Карточка сохраняет смысл случая, проходит проверку и открывается в каталоге без раскрытия диалога.

## Данные карточки

| Поля | Требование |
|---|---|
| ID, владелец, сессия | Постоянные связи и серверная проверка доступа |
| Название, задача и контекст | Понятные условия применимости |
| Действия, решения с основаниями, проверка результата | Содержание случая; существенные утверждения связаны с сообщениями или явными правками владельца |
| Ошибки, ограничения, неизвестное | Пробелы сохраняются, не дополняются моделью |
| origin | Неизменяемое human / synthetic |
| publication_status | draft / in_review / published |
| review_status | unreviewed / reviewed / needs_changes |
| Согласие, решение редактора, даты | Основание публикации; происхождение независимо от проверки |

## Проверки и готовность

| Случай | Ожидаемый результат |
|---|---|
| Нет основания выбора или материала мало | Частичный приватный черновик с пробелами |
| Рассказана неудача | Сохранена как неудача |
| Ссылка на чужую сессию | Результат отклонён |
| Сбой или повтор синтеза | Диалог сохранён, доступен повтор, второй экземпляр карточки не создаётся |
| Правка владельца | Исходный синтез сохранён; новые сведения различимы |
| Нет согласия или решения редактора | Публикация запрещена |
| Посторонний читает черновик или список черновиков | Чужие данные недоступны |
| Синтетический материал исправлен или принят редактором | origin остаётся synthetic |

Схему, доступ, повторы и переходы проверить автоматически; содержание — на сценариях роли 1 и реальном интервью. Результат роли: миграции, инструкция синтеза, примеры данных/API, работающие сохранение, правка, проверка и публикация.

## Основа для следующего этапа

Хранить карточки, сообщения и источники отдельно, связывать постоянными ID; происхождение и права проверять сервером независимо от канала ввода. Это база для дальнейшего развития по Dataflow. Сейчас не реализуем граф знаний, автоматическое слияние, версии наборов, embeddings, RAG и экспортный сервис; дубликаты проверяет редактор вручную. Самостоятельный реальный вклад оформляется отдельно от синтетического.

Коммиты и push — только после явного разрешения владельца.
