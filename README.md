# Modeus Interviewer

Основа MVP использует FastAPI, SQLAlchemy/Alembic и React/TypeScript/Vite. В браузере можно пройти интервью о рабочем случае, отредактировать карточку и отправить её редактору. После согласия автора и одобрения редактора карточка появляется в публичном каталоге. Тема появляется по ходу разговора.

[Технический контракт](Modeus_MVP_Technical_Contract.md) и [схема работы интервью](Modeus_Interview_Dataflow.md).

## Локальный запуск (PowerShell, из корня проекта)

Проверено на Python 3.14.6 и Node.js 24.20.0. Нужны Python 3.12+ и Node.js 22.12+; исполняемый Python должен работать, а не быть заглушкой Microsoft Store.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m ensurepip
.venv/Scripts/python.exe -m pip install -r requirements.lock
Copy-Item .env.example .env
New-Item -ItemType Directory -Force .work | Out-Null
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m backend.cli create-user your-email@example.com --editor
npm ci --prefix frontend
```

Пароль вводится интерактивно, в историю команд не попадает. Без `--editor` создаётся обычный участник. Саморегистрации нет: пилотных участников создаёт команда. Готовых паролей в репозитории нет. Повторное копирование `.env.example` поверх настроенного `.env` не требуется.

Терминал 1:

```powershell
.venv/Scripts/python.exe -m uvicorn backend.app:create_app --factory --host 127.0.0.1 --port 8000
```

Терминал 2:

```powershell
npm run dev --prefix frontend
```

Открыть **http://localhost:5173** (именно localhost: `APP_ORIGIN` должен совпадать). Vite проксирует `/api` на backend, браузер работает с одним origin. OpenAPI: http://127.0.0.1:8000/docs. Локальная БД — `.work/modeus.db`, она исключена из Git. Миграции выполняются явно, приложение не создаёт таблицы при импорте.

## Вход и ограничения текущего запуска

Почта/пароль → случайный непрозрачный токен в HttpOnly, SameSite=Lax cookie. В БД — только SHA-256 токена; срок по умолчанию 12 часов, выход отзывает сессию. Пароли хранятся как salted scrypt. Изменяющие auth-запросы требуют точного заголовка Origin; после пяти неверных паролей аккаунт блокируется на 15 минут. Общая зависимость `backend.auth.current_user` проверяет доступ к интервью и карточкам.

Локальный сервер слушает loopback и поддерживает HTTP. При HTTPS в `APP_ORIGIN` сессионная cookie автоматически получает `Secure`. OpenAPI и страницы документации доступны при локальных адресах приложения. Перед внешним пилотом нужны HTTPS, реальный `APP_ORIGIN`, ограничение частоты на reverse proxy, резервирование БД и проверка её прав. Сам backend ограничивает вход до 15 попыток в минуту на адрес клиента, а при блокировке аккаунта отзывает его сессии. Клиент не хранит токен в localStorage. Изменяющие запросы к интервью и карточкам требуют `Origin` и `Idempotency-Key`. Результаты команд доступны для повтора семь дней.

## Тон интервьюера

В анкете можно выбрать, как интервьюер формулирует вопросы: дружелюбный (по умолчанию), деловой или шутливый (`InterviewContext.tone`). Тон хранится в анкете, поэтому действует и в Telegram-боте. Вопросы модели получают тон из `TONES` и `TONE_REMINDERS`, фиксированные — первый вопрос, «Вспомните последний раз…», переход к новому случаю и запасные — из `FIXED_QUESTIONS` и `TONED_FALLBACKS` (всё в `backend/interview_engine.py`). Правила вопроса — одно предложение, обращение на «вы», без подсказок и похвалы — общие для всех тонов. Дружелюбные тексты — прежние слово в слово. Поэтому старые интервью и кэш ответов модели не меняются.

## Диктовка ответа

В web под полем ответа есть кнопка «Надиктовать» (`frontend/src/Dictation.tsx`). Речь распознаёт сам браузер через Web Speech API, язык — русский. Готовые фразы дописываются в поле, и их можно поправить перед отправкой; фраза, которую человек ещё произносит, видна под кнопкой. Работает в Chrome, Edge и Safari, в Firefox кнопки нет. Распознавание идёт не на нашем сервере: Chrome отправляет звук в Google, Safari — в Apple, об этом написано под кнопкой во время записи. Нужен доступ к микрофону и адрес `localhost` или HTTPS. В Telegram голосовые сообщения пока не распознаются.

## Telegram-бот

Интервью можно пройти в Telegram. Бот работает внутри backend и обращается к тому же API, что и web-клиент. Анкета, вопросы, повтор обработки, завершение и отправка карточки редактору подчиняются тем же правилам и лимитам.

1. Создайте бота у @BotFather и укажите токен в `.env`: `TELEGRAM_BOT_TOKEN=...`. Выполните `.venv/Scripts/python.exe -m alembic upgrade head` и перезапустите backend. Бот получает сообщения через long polling вместе с backend. На один токен запускайте один процесс: параллельный опрос Telegram отклоняет. Если api.telegram.org недоступен напрямую, задайте `HTTPS_PROXY`, поддерживается и `socks5://`.
2. Выдайте участнику приглашение: `.venv/Scripts/python.exe -m backend.cli telegram-invite your-email@example.com`. Команда печатает одноразовую ссылку `https://t.me/<бот>?start=<код>` и команду `/start <код>` для ручного ввода. Код действует 72 часа (`--hours`) и удаляется после использования. После перехода по ссылке Telegram связывается с аккаунтом, интервью из бота видны и в web.
3. Для демонстрации можно указать `TELEGRAM_OPEN_SIGNUP=true`. Тогда любой, кто откроет бота, получает отдельный аккаунт участника `telegram-<id>@telegram.invalid` без пароля для web. Пароль можно задать позже командой `reset-password`.

В чате `/new` начинает интервью с сохранённой анкетой. При первом запуске бот спрашивает, кем вы работаете, и предлагает рассказать об опыте, задачах и условиях работы. Основные поля можно обновить командой `/profile`, проекты — в веб-анкете того же аккаунта. На вопросы отвечают обычными сообщениями. Если Telegram разбил длинный текст на несколько сообщений, бот соберёт их в один ответ. Под вопросом есть кнопки «Пропустить» и «Завершить интервью». Пока модель работает, бот показывает этап обработки, а при сбое предлагает «Повторить». После завершения бот присылает карточку и предлагает отправить её редактору без имени или с подписью. Остальные команды: `/interviews` — список интервью, `/status` — текущий вопрос, `/skip`, `/finish`, `/cancel`, `/help`.

Бот принимает только текст в личных сообщениях. Проекты в анкете и правка карточки доступны в web. Состояние диалога хранится в БД: после перезапуска бот дошлёт вопросы, подготовленные без него.

## Бот MAX

Для пилота бот MAX получает сообщения через long polling вместе с backend. Публичный адрес не нужен. Запускайте один процесс на токен. Если для этого бота уже зарегистрирован webhook, снимите подписку перед запуском polling.

1. Укажите `MAX_BOT_TOKEN` в `.env`. Если сертификаты Минцифры не установлены в системное хранилище, скачайте корневой и выпускающий сертификаты со страницы [Госуслуг](https://www.gosuslugi.ru/crt). Соберите из них PEM-файл и добавьте `MAX_CA_FILE=.work/max-ca.pem` в `.env`. Пример для PowerShell, если файлы сохранены в `$env:TEMP`:

   ```powershell
   .\.venv\Scripts\python.exe -m backend.cli max-ca "$env:TEMP\max-root-ca.cer" "$env:TEMP\max-sub-ca.cer"
   ```

2. Выполните миграции и перезапустите backend.

   ```powershell
   .\.venv\Scripts\python.exe -m alembic upgrade head
   .\.venv\Scripts\python.exe -m uvicorn backend.app:create_app --factory --host 127.0.0.1 --port 8000
   ```

3. Выпустите приглашение для существующего аккаунта Modeus. Укажите опубликованный никнейм бота, чтобы получить ссылку. Команда также выводит `/start <код>` для ручного ввода в личном чате.

   ```powershell
   .\.venv\Scripts\python.exe -m backend.cli max-invite expert@example.com --bot BOT_USERNAME
   ```

В MAX используются та же анкета, интервью и карточки аккаунта. Приглашение одноразовое. После привязки нажмите «Начать интервью» или отправьте `/new`.

## LLM: настоящий проверочный запрос

В `.env` указать `LLM_BASE_URL` (точный OpenAI-совместимый API root), `LLM_MODEL` и при необходимости `LLM_API_KEY`. Затем:

```powershell
.venv/Scripts/python.exe -m backend.cli check-llm
```

Команда отправляет короткий запрос с JSON Schema и проверяет `{"ok":true}`. Ненастроенная модель, недоступный провайдер или неподдерживаемый structured output завершают проверку с ошибкой; заглушки нет. Ключ не передаётся frontend и не печатается. API-провайдер может тарифицировать этот запрос. В этой сессии провайдер не настроен, реальное подключение пока не подтверждено.

### Повторяемость ответов

Одинаковый запрос к модели всегда получает одинаковый ответ. Принятые ответы хранятся в таблице `llm_responses` по хэшу модели, параметров, промпта, схемы и входных данных; текст интервью туда не попадает. Повтор интервью и повторная попытка после сбоя берут сохранённый ответ без обращения к провайдеру. Ответ, не прошедший схему или проверку, не сохраняется и при повторе запрашивается снова. Изменение промпта, модели, `LLM_TEMPERATURE` или `LLM_SEED` даёт новый ключ. Карточка собирается без модели: факты идут в том порядке, в каком их назвал эксперт.

По умолчанию `LLM_TEMPERATURE=0`. `LLM_SEED` полезен для локального Ollama; у моделей Claude его нет. Пустое значение не передаёт параметр провайдеру. `check-llm` всегда обращается к провайдеру.

```powershell
.venv/Scripts/python.exe -m backend.cli clear-llm-cache                  # забыть все сохранённые ответы
.venv/Scripts/python.exe -m backend.cli clear-llm-cache --model qwen3:4b # только ответы одной модели
.venv/Scripts/python.exe -m scripts.evaluate_interview --repeat 5 --no-cache  # насколько стабильна сама модель
```

## Проверки

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m alembic check
.venv/Scripts/python.exe scripts/smoke.py
npm run build --prefix frontend
```

Тесты создают отдельную временную БД миграцией. Smoke запускает и останавливает собственный сервер. Для текущего проекта установлены фиксированные зависимости в `requirements.lock` и `frontend/package-lock.json`.

Для ручной проверки откройте страницу входа, войдите под созданным пользователем, обновите страницу и выйдите. После обновления сессия сохраняется, после выхода снова видна форма входа. Для полного закрытия шага 1 дополнительно выполните `check-llm` с выбранным провайдером. Успех — `"status": "ok"` и `"structured_output": true`. PostgreSQL проверяется отдельно перед серверным запуском.

Для проверки web-интервью укажите роль и начните диалог. Опишите конкретный рабочий случай, сохраните черновик и обновите страницу. Отправьте восстановленный ответ и дождитесь названия темы и уточнения. После разбора Modeus попросит описать другой случай. Завершите интервью вручную, затем откройте его из раздела «Мои интервью» и проверьте карточку.

Для репетиции показа используйте [синтетический SQL-сценарий `ambiguous`](data/interview/sql_scenarios.json). В нём запрос ускорился после изменения, но одновременно вышел другой релиз. Modeus уточняет, проверял ли участник эффект отдельно. В карточке сохраняются наблюдение и открытый вопрос о причине. При недоступной модели этот сценарий можно показать как заранее подготовленный пример.

### Публикация карточки

1. После обновления кода выполните `.venv/Scripts/python.exe -m alembic upgrade head` и перезапустите backend. Существующие карточки можно открыть через «Мои карточки».
2. Под участником откройте карточку, сохраните правки, отметьте согласие на публикацию и нажмите «Отправить редактору». Имя или псевдоним указывается по желанию, по умолчанию карточка публикуется без имени автора.
3. Под аккаунтом с ролью редактора откройте «Редактура» → «На проверке». Верните карточку с комментарием, затем под участником внесите правку и отправьте её повторно. Под редактором проверьте содержание и опубликуйте карточку.
4. Выйдите из аккаунта и откройте «Каталог». Затем под редактором откройте «Редактура» → «Опубликованные» и снимите карточку с указанием причины. После этого её ссылка в каталоге возвращает `404`.

Для проверки готовой карточки и её публикации доступ к LLM и HH API не требуется. Импорт вакансий HH — отдельная задача для уточняющих вопросов в интервью.

## Вакансии

Примени миграции и перезапусти backend. Для живого сбора задай в `.env` `HH_USER_AGENT` с названием приложения и контактной почтой разработчика. Укажи `HH_ACCESS_TOKEN` либо пару `HH_CLIENT_ID` и `HH_CLIENT_SECRET`. `HH_AREAS` принимает идентификаторы регионов через запятую. По умолчанию используется `113` (Россия). Живой сбор отправляет до трёх запросов в секунду, включая повторы. При ответе HH `429` учитывается `Retry-After`.

В разделе «Вакансии» редактор видит статус всех профилей, этап активного сбора и счётчики выбранного профиля. При сбое показывается последняя успешная выборка. Из консоли доступен тот же сбор:

```powershell
.venv/Scripts/python.exe -m backend.cli import-vacancies python_backend
```

Стартовые профили: `python_backend`, `frontend`, `qa`, `devops`. В разделе «Вакансии» редактор может добавить профессию вручную или выбрать новую роль из интервью. Укажи поисковый запрос для HH и синонимы, собери пробную выборку, затем нажми «Подтвердить для интервью». Изменение настроек требует нового сбора и подтверждения. Для локального прогона без HH добавь `--file .work/vacancies.json` с JSON-массивом полных ответов HH. Успешный прогон заменяет выборку выбранного профиля. При ошибке сохраняется предыдущая. При повторном сборе полные описания из последней выборки используются до 24 часов, если в выдаче HH не изменились название, дата публикации или требования к опыту. В результате сбора `details_fetched` и `details_reused` показывают число загрузок и попаданий в кэш. Пока backend запущен и HH настроен, сбор планируется на понедельник в 09:00 МСК. `HH_WEEKLY_ENABLED=false` оставляет ручной запуск.

Для подходящего кейса интервьюер получает до двух фрагментов вакансий из свежей выборки. По вопросу сохраняются ссылки на рассмотренные вакансии. Факты карточки по-прежнему подтверждаются ответами эксперта. Вакансии показывают задачи, требования и условия отдельно. Если модель указала, что использовала цитату, в диалоге её можно открыть под вопросом в разделе «Источник уточнения». Для парного прогона на одинаковых ответах используй команду `.venv/Scripts/python.exe -m scripts.evaluate_vacancy_context --samples 3 --output .work/vacancy-context-ab.json`.

«Работа России» обновляется через кнопку «Собрать данные по профессии». Токен не нужен. Для встроенных профилей используются поисковые фразы по роли, для остальных — название и до трёх синонимов. Бэкенд сохраняет до 50 подходящих вакансий с описанием обязанностей и ссылкой на источник. Список можно отфильтровать по источнику. HH и «Работа России» хранят свои выборки и даты сбора в одной БД. При сбое портала остаётся последняя успешная выборка. Для интервью подходят вакансии из подтверждённого профиля, если выборка собрана по текущим настройкам не более 14 дней назад. `TRUDVSEM_COLLECTION_ENABLED=false` отключает новые запросы к порталу.

## Проверенные источники для уточнений

После `alembic upgrade head` оператор может загрузить проверенные выдержки командой `.venv/Scripts/python.exe -m backend.cli import-sources .work/sources.json`. Файл содержит JSON-массив. В каждой записи укажи стабильный `id`, `profession_id`, `title`, официальный или оригинальный `url`, исходный `text`, `task`, дословную `quote` и `detail` — дословный фрагмент цитаты с деталью для уточнения. `kind` принимает `documentation`, `research`, `engineering` или `discussion`. `purpose` принимает `behavior` для поведения инструмента, `effect` для измеряемого эффекта и `implementation` для опыта внедрения. Повторный импорт обновляет запись по `id`.

Дополнительно можно указать `technology`, `version` (например, `16`), `conditions` (список коротких формулировок из рабочей среды) и `method` (дословное описание замера из источника). Для исследования эффекта обязательны условия и метод замера. Версионная выдержка подходит, когда из случая или связанного проекта можно определить соответствующую версию инструмента. Условия сопоставляются по явно названным фразам. При несовпадении роли, задачи, версии или условий интервью использует другие подходящие источники и может продолжиться по ответам эксперта.

Если несколько выдержек подходят одинаково, предпочтение отдаётся типу источника с большим весом для профессии — словарь `KIND_WEIGHTS` в `backend/source_context.py` (шкала 0–1, по умолчанию 0.5). Для инженерных профилей выше всего документация, для `ml_engineer` — научные статьи (`research: 1.0`). Новая профессия получает веса добавлением строки в словарь; релевантность задаче по-прежнему важнее веса.

## Мониторинг официальной документации

В разделе «Источники» выберите профессию и откройте «Мониторинг официальной документации». Стартовый набор для `python_backend` включает PostgreSQL 16 (планы запросов), SQLAlchemy 2.0 (разрывы соединений) и Celery stable (повторные попытки), а также журналы их релизов. Для любой профессии можно сохранить свой набор из реестра `backend/documentation_fetch.py`.

Кнопка «Проверить сейчас» запускает ту же операцию, что и расписание на понедельник в 09:00 МСК. После остановки backend догоняет пропущенную проверку при запуске. При временном сбое предыдущая редакция сохраняется, а плановый сбор повторяет попытку через 30 минут. Чтобы оставить только ручные проверки, укажите `DOCUMENTATION_WEEKLY_ENABLED=false` в `.env`.

## Эмбеддинги: поиск по смыслу и похожие случаи

Векторы считает локальная модель bge-m3 в Ollama через OpenAI-совместимый `/v1/embeddings`. Однократная настройка:

```bash
ollama pull bge-m3
```

В `.env`: `EMBEDDING_BASE_URL=http://localhost:11434/v1` и `EMBEDDING_MODEL=bge-m3`. Пустой `EMBEDDING_BASE_URL` выключает эмбеддинги: каталог ищет по совпадению слов, интервью подбирает контекст как раньше.

- Каталог: поле «Поиск по смыслу» с фильтром по категории навыков (`GET /api/v1/catalog/search?q=&category=databases`) и блок «Похожие случаи» на странице карточки (`GET /api/v1/catalog/{id}/similar`). Поиск ищет по случаям: карточка проходит, если её ближайший случай похож на запрос не меньше чем на 0,55, или от 0,5, но тогда у неё должно быть хотя бы одно общее слово с запросом — так запрос не по теме ничего не находит вместо случайной карточки. Порядок — близость плюс 0,1 × доля слов запроса, которые есть в карточке. У каждого результата видно, какой случай подошёл, его задача и навыки. Если модель не отвечает, поиск переключается на слова и возвращает `"mode": "words"`.
- Интервью: перед вопросом считается вектор текущего случая (не дольше 5 секунд). Задача из вакансии подходит при близости от 0,55, чужой опубликованный случай — от 0,6, даже без общих слов. Навыки, подтверждение задачи ответом и прежние проверки по словам остаются; среди подходящих задач вакансий выше стоят те, где больше общих слов, а близость по смыслу решает при равенстве.
- Темы и навыки (`#/catalog/themes`, `GET /api/v1/catalog/themes?threshold=0.64`): опубликованные случаи группируются по смыслу. Тему ведёт случай с наибольшим числом близких соседей, и каждый случай темы похож на него не меньше чем на 0,64. Матрица показывает корреляцию φ между «случай в теме» и «случай упоминает навык категории таксономии»: +1 — категория встречается только в этой теме, 0 — связи нет.
- Индексация: опубликованные карточки и задачи свежих вакансий векторизуются в фоне раз в 5 минут и сразу после публикации. Вектор пересчитывается, только если изменился текст или модель. Вручную: `python -m backend.cli embed-cards`.

Пороги выбраны замером `scripts/evaluate_embeddings.py` на наборах из `data/embeddings/`: 30 карточек, 28 запросов другими словами, 11 карточек о той же проблеме от другого человека и 32 задачи из вакансий.

| | по словам (было) | bge-m3 | nomic-embed-text |
|---|---|---|---|
| Поиск: нужная карточка первой | 15/28 | 23/28, с учётом слов 24/28 | 8/28 |
| Поиск: нужная карточка в тройке | 23/28 | 27/28 | 14/28 |
| Похожий случай первым | 9/11 | 10/11 | 1/11 |
| Подсказка из вакансии: верная / неверная | 16 / 1 из 41 | 25 / 1 из 41 | 26 / 15 из 41 |

Индекс HNSW (миграция `0027`) покрывает векторы bge-m3 размерности 1024; векторы другой модели ищутся точным перебором, без индекса. Сравнение на 20 000 синтетических векторов (`scripts/benchmark_vector_index.py`): точный перебор 47,7 мс на запрос, HNSW 2,2 мс при recall@10 0,97 (сборка 60 с), IVFFlat 12,4 мс при recall 1,00 (сборка 0,9 с). Взяли HNSW: быстрее и не требует данных в таблице на момент миграции, а IVFFlat учит свои списки по уже лежащим строкам. Пока карточек сотни, планировщик сам выбирает перебор — он дешевле.

Вектор запроса bge-m3 считается за 20–40 мс. В базе: таблицы `card_embeddings` и `text_embeddings` (миграция `0025`); на PostgreSQL с pgvector поиск идёт в SQL, иначе в Python. `copy-database` эти таблицы не переносит: фоновая индексация пересчитает их сама.

## PostgreSQL

Основная база — PostgreSQL 18 с расширением pgvector для эмбеддингов. SQLite остаётся запасным вариантом: без `DATABASE_URL` backend и тесты работают на нём. Не использовать одну SQLite-БД с нескольких машин.

macOS (формула `postgresql@18` не попадает в PATH сама):

```bash
brew install postgresql@18 pgvector
brew services start postgresql@18
export PATH="$(brew --prefix postgresql@18)/bin:$PATH"
psql -d postgres -c "create role modeus login password 'modeus' createdb"
psql -d postgres -c "create database modeus owner modeus"
psql -d modeus -c "create extension if not exists vector"
```

Windows: `winget install PostgreSQL.PostgreSQL.18`, затем те же три команды `psql` через `psql -U postgres`. pgvector не обязателен: без него векторы хранятся текстом и сравниваются в Python, как на SQLite.

В `.env` укажите `DATABASE_URL=postgresql+psycopg://modeus:modeus@localhost/modeus` и выполните `alembic upgrade head`. Драйвер `psycopg` ставится из `requirements.lock`.

Перенос данных из SQLite в свежую базу после миграций:

```powershell
.venv/Scripts/python.exe -m backend.cli copy-database sqlite:///./.work/modeus.db
```

Команда копирует все таблицы одной транзакцией и печатает число строк по каждой. Версии миграций обеих баз должны совпадать. Если в целевой базе уже есть пользователи, команда ничего не меняет. Перед переносом остановите backend.

Тесты на PostgreSQL: каждый тест создаёт и удаляет свою базу, поэтому роли нужно право `createdb`. Без переменной тесты идут на SQLite. Чтобы в тестовых базах был pgvector, суперпользователь один раз выполняет `psql -d template1 -c "create extension if not exists vector"`: обычная роль создать расширение не может.

```powershell
$env:TEST_DATABASE_URL="postgresql+psycopg://modeus:modeus@localhost/postgres"; .venv/Scripts/python.exe -m pytest -q
```

Текущая вершина миграций — `0027`. Хранение описано в `backend/db.py`, вход — в `backend/auth.py` и `backend/security.py`. За цикл интервью отвечают `backend/interview_api.py`, `backend/interview_worker.py` и `backend/interview_engine.py`. Публикация и каталог находятся в `backend/card_api.py`, боты — в `backend/telegram_bot.py` и `backend/max_bot.py`, код web — в `frontend/src`.
