| Компонент | Решение | Основание |
|---|---|---|
| Backend FastAPI | Берём технологию, самостоятельная реализация | В исходнике много зависимостей ML/аналитики, не нужных интервью |
| PostgreSQL/SQLAlchemy/Alembic | Адаптируем подход | Сохраняем ORM и миграции; SQLite для текущего локального запуска, PostgreSQL для сервера |
| Вход | Заменяем минимальным | Исходный вход связан с pgcrypto, учебными ролями, аудитом и TOTP. Здесь приглашённые пользователи, scrypt и отзываемые серверные сессии |
| LLM-клиент | Заменяем минимальным адаптером | Исходник поддерживает OpenAI-совместимый API, но тянет конфигурацию, метрики и запись стоимости в БД; его chat() не передаёт JSON Schema |
| React/Vite/TypeScript | Берём технологии, новый экран входа | Исходный dashboard обслуживает анализ компетенций; интервью требует другого пользовательского пути |
| hh.ru API и словари | Откладываем перенос | Клиент существует; связан с config, Result, моделями и кешем токенов. Для первой темы допустим ручной набор источников |
| ML, кеш LLM, мониторинг, n8n, учебные данные | Откладываем | Вне MVP |

## Зафиксированные решения

- Python 3.14.6; FastAPI 0.163.1; Uvicorn 0.54.0; SQLAlchemy 2.1.9; Alembic 1.20.1. Остальные версии — `requirements.lock`.
- Node.js 24.20.0; React 18.3.1; TypeScript 6.0.3; Vite 7.3.8; npm и package-lock. От тяжёлого исходного frontend взяты только технологические решения.
- Вход: почта/пароль для приглашённых участников, серверные сессии, HttpOnly cookie; редактор назначается CLI.
- Runtime Python найден по `C:\Users\vladg\AppData\Local\Python\pythoncore-3.14-64\python.exe`; команда `python` в PATH оказалась неработающей заглушкой Store. Создана `.venv`.
- Docker CLI установлен, Linux daemon не работает; PostgreSQL в этой сессии не проверен. SQLite запускается без Docker.
- `.env` отсутствовал; подходящих настроек LLM в окружении не было. CLI завершился `LLM_NOT_CONFIGURED`. Адрес чужой Ollama из исходного compose не используется как доступ пользователя.

Команды запуска и проверок — в [README](../README.md). Реальный вызов LLM остаётся условием закрытия шага: пользователь задаёт свой endpoint/model/key в локальном `.env`, команда `check-llm` должна завершиться успешно. Секреты в чат и репозиторий не передаются.
