# Шаг 3. Текстовое интервью и приватный черновик

Backend принимает анкету, сохраняет первый вопрос и позволяет записать или исправить черновик ответа. После отправки ответа модель классифицирует фразы. Сервер берёт цитаты из исходного сообщения и выбирает цель следующего вопроса. Модель формулирует вопрос по этой цели, а для некоторых сценариев сервер использует готовую формулировку. Завершение собирает приватную карточку из фактов со ссылками на ответы и списком пробелов.

На этом этапе факты хранятся как проверяемые цитаты. При синтезе модель упорядочивает их, а сервер формирует текст карточки. Если интервью завершено до успешного извлечения, соответствующие сведения остаются пробелами. Отправленный текст сохраняется в диалоге.

## Запуск

Из корня проекта при запущенном Ollama:

```powershell
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m scripts.seed_interview
.venv/Scripts/python.exe -m backend.cli check-llm
.venv/Scripts/python.exe -m uvicorn backend.app:create_app --factory --host 127.0.0.1 --port 8000
```

Если backend уже работал, перезапустите его после миграции. Миграция `0003` добавляет карточки, подтверждения выполнения команд и поля для восстановления заданий. Если процесс остановлен посреди обработки, новый worker сможет взять задание после окончания его аренды.

Для локальной Qwen3 в Ollama можно задать `LLM_REASONING_EFFORT=none`, чтобы сократить время ответа. Для провайдера, который не поддерживает этот параметр, поле остаётся пустым.

Команда `.venv/Scripts/python.exe -m scripts.smoke_interview` прогоняет синтетический ответ через реальную модель и печатает вопрос и черновик. Она использует временную SQLite и текущие настройки LLM.

## Проверка через API

Операции идут под `/api/v1`. После входа сохраняйте cookie в HTTP-клиенте. Изменяющим запросам нужен заголовок `Origin`, совпадающий с `APP_ORIGIN` из `.env`. Для создания интервью и каждой команды передавайте новый `Idempotency-Key`. При сетевом повторе используйте прежний ключ и то же тело.

| Действие | Запрос | Что проверить |
|---|---|---|
| Войти | `POST /auth/login` с почтой и паролем | `200`, cookie сессии |
| Получить тему | `GET /topics` | Есть `sql-slow-query` |
| Создать интервью | `POST /interviews` с анкетой | `201`, получен ID |
| Получить первый вопрос | `GET /interviews/{id}` | После обработки `idle`, есть `current_question_id` |
| Сохранить черновик | `POST /interviews/{id}/answers` с текущей версией, ID вопроса и текстом | `201`, новый ответ в статусе `draft` |
| Отправить черновик | `POST /interviews/{id}/answers/{answer_id}/submit` с версией после сохранения | `202`, ответ поставлен в обработку |
| Прочитать результат | `GET /interviews/{id}` | Сохранён следующий вопрос по текущему или новому случаю. При `failed` видна ошибка и доступен `POST /interviews/{id}/retry` с актуальной версией |
| Завершить | `POST /interviews/{id}/finish` с актуальной версией | `202`. После завершения чтение интервью возвращает `card_id` |
| Открыть черновик | `GET /cards/{card_id}` | Владелец получает `draft` со ссылками на ответы, другой пользователь получает `404` |

Точные тела запросов описаны в [примере первого хода](../data/interview/first_turn.json). Версия может измениться по мере обработки, поэтому при `409 VERSION_CONFLICT` перечитайте состояние. Набор проверок API запускается командой `.venv/Scripts/python.exe -m pytest -q`. Полноценный экран интервью, редактура и публикация предусмотрены последующими шагами.
